# maarshir.github.io

[![Тесты](https://github.com/maarshir/maarshir.github.io/actions/workflows/tests.yml/badge.svg?branch=main)](https://github.com/maarshir/maarshir.github.io/actions/workflows/tests.yml)

Мой сайт-резюме: https://maarshir.github.io. Кто я, проекты со ссылками на код, образование, стек и контакты на одной странице в пиксельном стиле.

На широком экране сайт открывается пиксельным городком: гость ходит персонажем между зданиями, а каждое здание это проект. Арена для promptdiff, Библиотека для doc-answers, Счётная контора для token-counter, Мастерская для ассистента, Сад желаний для Wishly, ещё Дом, Почта и доска объявлений на площади. Гулять можно стрелками, WASD или кликом по карте. У двери появляется табличка, Enter, пробел или клик по зданию открывают пиксельное окно: текст печатается, как в старой игре, ниже стек и кнопка «Код на Гитхабе». В Доме коротко обо мне, на Почте контакты, на доске объявлений то, над чем работаю сейчас.

Для тех, кому некогда, есть обычный режим, страница «всё за 30 секунд»: кнопка в углу городка и прямая ссылка https://maarshir.github.io/#cv, её можно вставить в отклик. На телефоне и без JavaScript первым открывается обычный режим, городок по кнопке или по ссылке /#town.

## Как запустить у себя

Нужен Node.js 20 или новее, зависимостей нет.

```bash
git clone https://github.com/maarshir/maarshir.github.io
cd maarshir.github.io
npm test          # проверки данных, сборки и ссылок
npm start         # то же, что python3 -m http.server 8000
```

Сайт откроется на http://localhost:8000. Обычный режим работает и просто из файла, без сервера. Городку нужен сервер: окна зданий читают data/*.json через fetch, а из file:// браузер это не отдаёт.

Поменять текст на сайте:

```bash
# правим data/profile.json или data/projects.json
npm run build     # пересобирает index.html и значок вкладки
npm test
```

## Как устроено

```text
data/profile.json    кто я, обо мне, образование, работа, стек, контакты
data/projects.json   проекты: описание, пункты, стек, ссылка на код, здание в городке
js/render.mjs        проверка данных и сборка HTML обычного режима
js/avatar.mjs        пиксельный аватар 16×16 строками букв и перевод его в SVG
js/town/map.mjs      карта городка: тайлы, здания, двери, точка появления
js/town/physics.mjs  движение и столкновения у ног персонажа
js/town/path.mjs     поиск пути по клику (A*) и ближайший свободный тайл
js/town/camera.mjs   целый масштаб пикселей и мягкая камера
js/town/mode.mjs     что показать первым: городок или обычный режим
js/town/sprites.mjs  персонаж в четырёх направлениях, дерево, знаки зданий
js/town/draw.mjs     рисование карты и персонажа на canvas
js/town/interact.mjs какое здание рядом, текст подсказки и окна из данных, печатная машинка
js/town/main.mjs     связка с браузером: цикл кадров, клавиатура, клик, подсказка и окно здания
scripts/build.mjs    вставляет собранный HTML в index.html между метками, собирает favicon.svg
css/site.css         палитра, пиксельные рамки, светлая и тёмная тема, печать
css/town.css         городок на весь экран и переключение режимов
fonts/               пиксельный шрифт Tiny5, встроенный в CSS, и его лицензия
test/                тесты на встроенном node --test
```

Все факты лежат в двух JSON-файлах. Когда в другом проекте что-то меняется, сайт обновляется одной правкой данных и `npm run build`. Окна зданий в городке читают те же файлы, поэтому обычный режим и игра не разойдутся.

Логика городка (карта, столкновения, путь, камера, выбор режима, какое здание рядом и что написать в его окне) лежит в модулях без обращения к странице, поэтому её проверяют обычные тесты на Node. С браузером работает только js/town/main.mjs. Карта не нарисована символ за символом, а собрана из прямоугольников: дороги, площадь, пруд, деревья. Тест сам проверяет, что от точки появления можно дойти до двери каждого здания, так что при правке карты случайно замуровать дом не получится.

## Технологии и почему они

- **Обычный HTML, CSS и JavaScript без фреймворков.** Страница весит несколько десятков килобайт вместе со шрифтом и открывается сразу. Для городка хватит canvas, фреймворк тут ничего не даёт.
- **Сборка при публикации, а не в браузере.** Обычный режим собирается из JSON скриптом и лежит в index.html готовым текстом. Поэтому он виден без JavaScript, его читают поисковики и превью ссылок в мессенджерах, и нет мигания пустой страницы. Тест сверяет index.html с данными: если данные поменяли, а собрать забыли, тесты упадут.
- **GitHub Pages.** Бесплатно, без сервера, адрес вида maarshir.github.io.
- **Шрифт встроен в CSS.** Tiny5 под лицензией SIL OFL 1.1 с кириллицей. Он лежит прямо в css через data-адрес: сайт не ходит на внешние серверы шрифтов, которые могут не открыться.

## Что было трудным

- **Пиксельный шрифт с нормальной кириллицей.** Первый выбранный шрифт (Pixelify Sans) по лицензии подходил, но в нём буква К с завитком читалась как Ќ, а «Иван» выглядел как «Ивaн». Сравнил на одной строке три свободных шрифта с кириллицей и взял Tiny5: буквы узнаются сразу. Для длинного текста оставил системный шрифт, пиксельный только в заголовках, кнопках и подписях: иначе абзацы тяжело читать.
- **Пиксель-арт без картинок.** Аватар записан как 16 строк по 16 букв, каждая буква это цвет. Скрипт превращает его в SVG и склеивает соседние пиксели одного цвета в один прямоугольник, так разметка короче в несколько раз. `shape-rendering="crispEdges"` не даёт размыть края при увеличении. Тот же спрайт стал значком вкладки, а персонаж городка нарисован так же и в тех же цветах, только во весь рост и в четырёх направлениях.
- **Чтобы данные не врали.** Проверка данных отказывается собирать страницу, если у проекта нет описания или стека, ссылка ведёт не в мой Гитхаб, два проекта заняли одно здание или ссылка «Попробовать» не https. Все тексты экранируются при сборке. Отдельный тест ищет в данных длинные тире и слова из рекламных буклетов.
- **Тёмная тема и контраст.** Доска «Сейчас работаю над» в тёмной теме сначала получилась светло-коричневой с бледным текстом. Поправил на один тёмный цвет дерева в обеих темах, текст на нём читается.
- **Столкновения, в которых не застреваешь.** Если проверять весь спрайт 16×16, персонаж цепляется плечом за угол дома и не пролезает в проход шириной в тайл. Поэтому сталкиваются только ноги, прямоугольник 10×6 у низа спрайта, а голова может зайти на стену, как в старых играх. Движение считается отдельно по x и по y: если упёрся в стену, по другой оси продолжаешь скользить вдоль неё. Длинный шаг режется на куски по 4 пикселя, а точка касания ищется делением пополам, поэтому при подвисшей вкладке персонаж не проскакивает сквозь забор.
- **Чёткие пиксели на любом экране.** Масштаб только целый (2, 3, 4...), иначе одни пиксели выходят шире других. Холст рисуется в маленьком размере карты, а растягивает его браузер с `image-rendering: pixelated`. Неподвижная часть карты рисуется один раз в отдельный холст, в каждом кадре копируется только видимый кусок и сверху персонаж.
- **Камера, которая не зависит от частоты кадров.** Простое «догнать на 10% за кадр» на мониторе 144 Гц работает вдвое быстрее, чем на 60 Гц. Здесь доля пути считается как `1 - exp(-rate * dt)`, и за одно и то же время камера проходит одинаковый путь при любой частоте, это проверяет тест. При `prefers-reduced-motion` камера не плывёт, а сразу стоит где надо.
- **Окно, которое печатает текст и при этом доступно.** Если печатать текст прямо в абзац, окно растёт с каждой строкой и кнопки прыгают вниз, а читалка экрана зачитывает обрывки. Поэтому в абзаце лежат три куска: полный текст только для читалки, напечатанная часть и ещё не напечатанный остаток с `visibility: hidden`. Место под весь текст занято сразу, ничего не прыгает, а читалка слышит абзац целиком. Первое нажатие Enter или клик показывает всё сразу, при `prefers-reduced-motion` печати нет вовсе. Окно модальное: фокус переходит в него, Tab ходит по его кнопкам и не уходит на карту, Esc закрывает и возвращает фокус на карту. Текст из данных вставляется через textContent, так что разметка из JSON не выполнится.
- **Какое здание рядом.** Подсказка появляется, когда ноги персонажа ближе 12 пикселей к месту перед дверью. Порог меньше тайла, поэтому зоны соседних дверей не пересекаются, это проверяет тест. Клик по зданию ведёт персонажа к двери и открывает окно, когда он дошёл; если по дороге гость нажал стрелку, окно не откроется само.
- **Страница не мигает.** Модули грузятся после отрисовки, и широкий экран успел бы на миг показать обычный режим. Поэтому что показать первым, решает крошечный скрипт в `<head>`. Правило записано дважды (там и в mode.mjs), и тест запускает скрипт из index.html в песочнице на разных ширинах и якорях и сверяет ответы с модулем. Если модуль городка не загрузился, вместо пустого экрана видна ссылка на обычный режим.
