# maarshir.github.io

Показывает резюме и проекты в пиксельном стиле: [maarshir.github.io](https://maarshir.github.io).

[![Тесты](https://github.com/maarshir/maarshir.github.io/actions/workflows/tests.yml/badge.svg?branch=main)](https://github.com/maarshir/maarshir.github.io/actions/workflows/tests.yml)

[![Первый экран сайта с ответом на вопрос «Что умеешь?»](docs/screen.png)](https://maarshir.github.io)

На первом экране пиксельный персонаж печатает за компьютером, а за окном утро, день, вечер или ночь по часам гостя. Рядом окно «Спросите моё резюме»: можно нажать готовый вопрос или написать свой. Отвечает не нейросеть, а поиск по данным сайта прямо в браузере, как в [doc-answers](https://github.com/maarshir/doc-answers), и под ответом видно, где он нашёлся. Ниже карточки проектов в виде картриджей.

Для любопытных внизу есть пасхалка: пиксельный городок, где проекты стоят домами и по ним можно погулять персонажем ([прямая ссылка](https://maarshir.github.io/#town)).

## Как запустить у себя

```bash
git clone https://github.com/maarshir/maarshir.github.io
cd maarshir.github.io
npm test     # проверки данных, сборки, доступности и веса страницы
npm start    # сайт на http://localhost:8000 (нужен python3)
```

Нужен Node.js 20 или новее, для самой страницы и тестов зависимостей нет. Все тексты лежат в `data/profile.json` и `data/projects.json`, тексты резюме PDF в `data/resume.json`. После правки данных:

```bash
npm run build                               # index.html, favicon.svg, resume.html и превью из data/*.json
npm ci                                      # один раз: playwright-core для PDF и картинки превью
npx playwright-core install chromium        # один раз: Chromium
npm run assets                              # resume.pdf и assets/og.png
```

На Гитхабе те же команды выполняет `build.yml` после каждого пуша с изменёнными данными или кодом сборки, поэтому данные можно править прямо в браузере. Снимок экрана для этого README обновляет `screenshot.yml`.

## Как устроено

```text
data/*.json -> npm run build -> index.html, resume.html, assets/og-card.html
                                resume.html, og-card.html -> npm run assets (Chromium) -> resume.pdf, assets/og.png
в браузере:  index.html + js/ask.mjs   поиск по разделам data/*.json для «Спросите моё резюме»
             /#town -> js/town/        городок на canvas из того же data/projects.json
```

- **Обычный HTML, CSS и JavaScript без фреймворков.** Страница вместе со шрифтом, CSS и JS весит около 170 килобайт и открывается сразу.
- **Страница собирается заранее.** HTML готов ещё до открытия, поэтому сайт виден без JavaScript, его читают поисковики и превью ссылок в мессенджерах.
- **Один источник правды.** Главная, картинка превью и окна в городке берутся из тех же двух файлов данных и не могут разойтись. Резюме PDF берёт оттуда имя и контакты, а свои тексты из `data/resume.json`.

## Что было непросто

- **Городок был входом, а стал пасхалкой.** Сначала сайт открывался игрой, но гость не станет гулять по карте, чтобы найти проекты. Теперь первой открывается обычная страница, а городок ждёт внизу.
- **Пиксельный шрифт с нормальной кириллицей.** В первом шрифте «К» читалась как «Ќ». Из трёх свободных шрифтов подошёл Tiny5, и он только в заголовках.
- **Поиск по резюме без сервера и модели.** Ответ ищется в браузере: слова сводятся к основам, разделы данных ранжируются по BM25, ответ собирается только из найденного раздела, и под ним видно, откуда он. Ключи и сервер не нужны. Сложнее всего было с вопросами другими словами: «Где учился?» должен находить «Образование», хотя слова «учился» там нет. Помогли подсказки к разделам и синонимы, а тесты проверяют десяток с лишним обычных вопросов.
- **Резюме PDF из тех же данных.** `resume.html` переводится в PDF через Chromium из Playwright, поэтому вёрстка резюме обычные HTML и CSS со своим шрифтом. Пересобрать PDF байт в байт нельзя (дата внутри, шрифты у версий Chromium разные), поэтому рядом лежат хэши исходного HTML, и тест падает, если PDF забыли обновить.
- **Контраст и фокус.** В светлой теме красный текст и жёлтая рамка фокуса не дотягивали до WCAG 2.1 AA, их пришлось затемнить, а в городке на зелёном фоне рамка осталась светлой. Тест считает контраст цветов прямо из CSS в обеих темах, проверяет видимую рамку фокуса с клавиатуры, порядок Tab и подписи кнопок и полей.
- **Телефон и вес страницы.** Длинные ссылки ломали ширину на телефоне. Теперь тест ищет в CSS ширины больше 360px вне медиазапросов, проверяет переносы, размеры картинок, ленивую загрузку и скрипты без задержки отрисовки, а вес `index.html` с CSS и JS держит под порогом, чтобы страница не разрасталась незаметно.
- **Ходить по городку и не застревать.** Сталкиваются только ноги персонажа, а движение по осям считается отдельно, поэтому он скользит вдоль стен. Тест проверяет, что до двери каждого дома можно дойти.

Подробнее: [docs/решения.md](docs/решения.md), про резюме и превью: [docs/резюме-и-превью.md](docs/резюме-и-превью.md).
