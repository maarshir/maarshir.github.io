# maarshir.github.io

[![Тесты](https://github.com/maarshir/maarshir.github.io/actions/workflows/tests.yml/badge.svg?branch=main)](https://github.com/maarshir/maarshir.github.io/actions/workflows/tests.yml)

Первый экран: имя, одна фраза и кнопки «Проекты», «Написать в Телеграм», «Гитхаб», под ними пиксельная сцена: персонаж печатает за компьютером, а за окном утро, день, вечер или ночь по часам гостя. Рядом окно «Спросите моё резюме»: готовые вопросы («Что умеешь?», «Где учился?») и поле для своего. Отвечает не нейросеть, а поиск по data/*.json прямо в браузере, по тому же принципу, что в [doc-answers](https://github.com/maarshir/doc-answers): основы слов и BM25. Ответ печатается, под ним видно, в каких разделах и по каким словам он нашёлся, и ссылки туда. Если ничего не нашлось, так и сказано, и предложен Телеграм. Ниже два раздела: «Проекты» (promptdiff, doc-answers, gost-skills) и «Личные проекты» (небольшие вещи, сделанные для себя). Карточки сделаны как картриджи с цветной наклейкой и проявляются при прокрутке. На карточке название, одна строка, до трёх меток стека и ссылка на код, если код открыт; подробности свёрнуты под «Подробнее». На широком экране вдоль правого края шагает маленький персонаж, пока страница прокручивается. При включённом в системе уменьшении движения сцена стоит, карточки видны сразу, персонажа у края нет.

Внизу пасхалка: кнопка «Погулять по пиксельному городку» (или прямая ссылка https://maarshir.github.io/#town). Там по тем же проектам можно пройтись персонажем: здания это проекты, у двери Enter открывает окно с печатающимся текстом.

## Как запустить у себя

Нужен Node.js 20 или новее, зависимостей нет.

```bash
git clone https://github.com/maarshir/maarshir.github.io
cd maarshir.github.io
npm test          # проверки данных, сборки и ссылок
npm start         # то же, что python3 -m http.server 8000
```

Сайт откроется на http://localhost:8000. Главная работает и просто из файла, без сервера. Чату и городку нужен сервер: они читают data/*.json через fetch, а из file:// браузер это не отдаёт.

Поменять текст на сайте:

```bash
# правим data/profile.json или data/projects.json
npm run build     # пересобирает index.html и значок вкладки
npm test
```

## Как устроено

```text
data/profile.json    кто я, обо мне, образование, работа, стек, контакты
data/projects.json   проекты: раздел (main или personal), строка для карточки, описание, стек, код и здание в городке (null, если кода или здания нет)
js/render.mjs        проверка данных и сборка HTML главной страницы
js/avatar.mjs        пиксельный аватар 16×16 строками букв и перевод его в SVG
js/ask.mjs           «Спросите моё резюме»: основы слов, BM25 по разделам, сборка ответа из данных
js/chat.mjs          окно чата в браузере: кнопки, поле, печать ответа
js/typewriter.mjs    печатная машинка, общая для чата и окон городка
js/scene.mjs         пиксельная сцена первого экрана в SVG и время суток по часу гостя
js/walker.mjs        персонаж у края: место от доли прокрутки, направление, кадр шага
js/live.mjs          связка сцены, появления карточек и персонажа у края с браузером
js/town/map.mjs      карта городка: тайлы, здания, двери, точка появления
js/town/physics.mjs  движение и столкновения у ног персонажа
js/town/path.mjs     поиск пути по клику (A*) и ближайший свободный тайл
js/town/camera.mjs   целый масштаб пикселей и мягкая камера
js/town/mode.mjs     что показать: главную или городок (только по /#town)
js/town/sprites.mjs  персонаж в четырёх направлениях, дерево, знаки зданий
js/town/draw.mjs     рисование карты и персонажа на canvas
js/town/interact.mjs какое здание рядом, текст подсказки и окна из данных
js/town/main.mjs     связка с браузером: цикл кадров, клавиатура, клик, подсказка и окно здания
scripts/build.mjs    вставляет собранный HTML в index.html между метками, собирает favicon.svg
css/site.css         палитра, пиксельные рамки, светлая и тёмная тема, печать
css/town.css         городок на весь экран, кнопка в него внизу главной
fonts/               пиксельный шрифт Tiny5, встроенный в CSS, и его лицензия
test/                тесты на встроенном node --test
```

Все факты лежат в двух JSON-файлах. Когда в другом проекте что-то меняется, сайт обновляется одной правкой данных и `npm run build`. Окна зданий в городке читают те же файлы, поэтому главная и городок не разойдутся.

Логика городка (карта, столкновения, путь, камера, выбор режима, какое здание рядом и что написать в его окне) лежит в модулях без обращения к странице, поэтому её проверяют обычные тесты на Node. С браузером работает только js/town/main.mjs. Карта не нарисована символ за символом, а собрана из прямоугольников: дороги, площадь, пруд, деревья. Тест сам проверяет, что от точки появления можно дойти до двери каждого здания, так что при правке карты случайно замуровать дом не получится.

## Технологии и почему они

- **Обычный HTML, CSS и JavaScript без фреймворков.** Страница весит несколько десятков килобайт вместе со шрифтом и открывается сразу. Для городка хватит canvas, фреймворк тут ничего не даёт.
- **Сборка при публикации, а не в браузере.** Главная собирается из JSON скриптом и лежит в index.html готовым текстом. Поэтому она видна без JavaScript, её читают поисковики и превью ссылок в мессенджерах, и нет мигания пустой страницы. Тест сверяет index.html с данными: если данные поменяли, а собрать забыли, тесты упадут.
- **GitHub Pages.** Бесплатно, без сервера, адрес вида maarshir.github.io.
- **Шрифт встроен в CSS.** Tiny5 под лицензией SIL OFL 1.1 с кириллицей. Он лежит прямо в css через data-адрес: сайт не ходит на внешние серверы шрифтов, которые могут не открыться.

## Что было трудным

- **Городок был входом, а стал пасхалкой.** Сначала на широком экране сайт открывался игрой, а страница «всё за 30 секунд» была запасной. По исследованиям (Nielsen Norman Group о первых 10 секундах на странице, Ladders о 7 секундах на резюме) и по ощущению от готового городка выходило, что гость не станет гулять, чтобы найти проекты. Поэтому первой на всех экранах открывается обычная страница, а городок остался по кнопке внизу. Код городка не выбрасывал: он берёт данные из тех же файлов.
- **Пиксельный шрифт с нормальной кириллицей.** В первом шрифте К читалась как Ќ. Сравнил три свободных шрифта и взял Tiny5; пиксельный только в заголовках и кнопках, абзацы системным шрифтом.
- **Чтобы данные не врали.** Сборка отказывается работать, если у проекта нет строки или стека, раздел не main и не personal, ссылка ведёт не в мой Гитхаб или для кнопок первого экрана нет Телеграма и Гитхаба. Тексты экранируются, тест ищет длинные тире и рекламные слова.
- **Столкновения, в которых не застреваешь.** Сталкиваются только ноги персонажа, а движение по осям считается отдельно, поэтому он скользит вдоль стен и не цепляется плечом за углы.
- **Поиск по резюме без модели.** Нужно было, чтобы «Где учился?» находил раздел «Образование», где слова «учился» нет, а «проекты с ИИ» не уводил в общий раздел «Обо мне». Помогли три вещи: короткие подсказки к разделам (как о них обычно спрашивают), синонимы для слов, которых в резюме нет дословно («ИИ» это модели и промпты), и правила «проект назван по имени, отвечает он один» и «спросили про проекты, отвечают карточки». Тест проверяет готовые кнопки, десяток с лишним обычных вопросов и то, что ответ берётся только из данных.
- **Сцена, у которой меняется время суток, без перерисовки.** Сцена собирается в SVG при сборке и видна без JavaScript (днём). Скрипт только ставит атрибут `data-phase`, а цвет неба, солнце, луну и свет лампы решает CSS. Ночь сделана одной полупрозрачной тенью поверх комнаты; небо, экран и лампа лежат выше тени и поэтому светятся в темноте, порядок слоёв проверяет тест.
- **Окно, которое печатает текст и при этом доступно.** Место под весь текст занято сразу, поэтому окно не прыгает, а читалка экрана слышит абзац целиком.

Подробнее обо всём этом и о других решениях: [docs/решения.md](docs/решения.md).
